# Stable classic HomeKit live clocks

This slice changes source/presentation/RTP correlation only. It preserves selected codecs, classic-HAP audio rates, packet pacing, bitrates, freshness limits, crypto contexts and native-resource ownership. It does not add playout delay or claim a physical Apple pause is fixed.

`LiveTimeline` is one view-owned, event-loop-owned metadata object for video90kHz and original audio48kHz rescaled to selected8/16/24kHz. The live manager creates it after START validation; the audio track shares that exact object. Original inputPTS/receipt/epoch and immutable source-clock observations enter before conversion. R6a's output provenance remains responsible for identifying the original input that produced a returned picture.

The first actual mapping freezes its mode for that capture epoch. Source mode requires all enabled tracks' first actual inputs and recent coherent source reports, plausible cross-track relation, and first projections within the existing five-second sanity boundary of original receipts. Otherwise the mode is honestly `receiver_estimated`: each track uses its first original inputPTS/receipt as a fixed affine estimate. Late, duplicate, reordered or inconsistent source reports can change bounded confidence metadata, never the established media timeline. Missing sender clocks cannot prove the true source A/V phase.

Every output sample derives its presentation and outgoing RTP timestamp from its original sourcePTS. Three20ms outputs released by one60ms audio input therefore remain three separate sample instants, including negative encoder lookahead. Same-epoch codec reconfiguration resets dependency recovery/cache state, not source-time origin. An actual capture epoch starts a new input mapping while preserving the view's RTP origin and elapsed presentation domain; late old-epoch inputs/outputs cannot rebase it. Regressing output is refused rather than assigned an invented timestamp.

One monotonic/wall pair initializes the report clock. Each report uses one subsequent monotonic instant and signed affine extrapolation for both its RTP value and corresponding projected wall time; future sample instants are not clamped to zero elapsed. A track becomes reportable only after its actual successful media send in that epoch. A reset does not allow an old track's last-send fact to authorize new-epoch reports. Packet/SSRC/SRTP state and successful-send counters retain their existing owners.

The object retains fixed metadata for at most two tracks. Diagnostic snapshots expose fixed confidence/counter fields, not source SSRCs, raw NTP values, addresses, payloads or RTP origins. Existing permission, capture-epoch, queue, socket-admission and retirement fences remain in place. Original receipts still govern500ms freshness independently of presentation mapping.

Qualification includes deterministic known counterexamples (late SR rebasing, batched-output presentation collapse, same-epoch gap compression, signed future-anchor reports, wrap, old epochs and no report before new media). Composed tests use actual native true monoWB/SILK60ms input→20ms Opus, protected local UDP audio/video, independent decoders, and outgoing SR correlation. The known100ms source A/V offset is recovered as97.5ms for the first audio packet because its actual encoder lookahead is2.5ms. This validates emitted timestamps, not Apple render behavior.

The optional old `AudioTrack` constructor `presentation` keyword remains accepted for internal-call compatibility, but no independent callback can override the shared timeline. Standalone internal audio probes lazily create the same estimator; production START always supplies the parent-owned shared object.
